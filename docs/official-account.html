公众号接入指南

公众号是 Sona 内的运营主体：用户关注后可以像聊天一样收到推送、点击菜单、与客服对话。 本文覆盖账号申请、消息收发、内联按钮、自定义菜单、自动回复与客服协作。

1接入前必读

  • 鉴权方式：公众号接口沿用 Sona 登录态，请求头带 token（OpenIM 用户 Token），服务端据此确定调用者身份，不信任请求体里的身份字段。
  • 权限模型：账号有创建者（owner）与成员（member）之分，成员权限由 owner 授予；未授权调用返回 2002 无权限操作。
  • 幂等：所有写接口都必须带 clientReqID（≤128 字符），同值重复提交返回同一结果，不会重复发消息。
  • 错误返回：统一 { code, message, data }；文案已中文化，不会暴露底层异常。
接口基地址与 OpenIM 业务服务一致（生产环境为 http://<server>:10020，与钱包等业务共用同一网关）。

2申请公众号

提交资料后进入审核队列，审核通过即可获得 accountID。

POST /official/account/apply
{
  "type": "service",          // 账号类型
  "name": "示例服务号",
  "avatarURL": "https://.../avatar.png",
  "description": "订单通知与售后客服"
}

4接收用户消息（入站回调）

用户发给公众号的文本消息，通过 OpenIM 的 afterSendSingleMsg 回调推送到你的服务，落库后可在会话里查看。

4.1 配置回调地址

  • 在 OpenIM 配置里把 afterSendSingleMsg 的回调 URL 指向：http://<host>:10020/official/webhook/message
  • 同时配置共享密钥，服务端会校验请求头 X-Webhook-Secret
  • 未配置密钥时该路由不注册，接口返回 404

4.2 请求体（OpenIM 回调格式）

POST /official/webhook/message
X-Webhook-Secret: <your-secret>
Content-Type: application/json

{
  "sendID": "8454036619",
  "recvID": "official_10001",
  "serverMsgID": "abc...",
  "contentType": 101,        // 仅文本消息会入库
  "content": "{\"content\":\"你好，我要查订单\"}"
}

服务端解析 content 里的 {"content": "..."} 取正文；非文本消息直接返回成功并忽略。

4.3 返回约定

HTTPerrCode含义
2000已入库
4012001回调密钥校验失败
4001002请求格式错误 / 参数缺失 / 内容解析失败
5005001系统异常（可重试）

5发送消息（出站）

POST /official/message/send
{
  "accountID": "official_10001",
  "userID": "8454036619",
  "kind": "text",              // text | template
  "body": "您的订单已发货",
  "clientReqID": "order-20261114-0001",
  "buttons": [                 // 可选，仅公众号发给用户时允许
    { "text": "查看详情", "type": "route", "value": "/order/detail?id=1" },
    { "text": "联系客服", "type": "callback", "value": "contact_service", "payload": "{\"order\":\"1\"}" }
  ]
}

字段约束

字段约束
kind仅 text / template，缺省为 text
body1–2000 字符
clientReqID必填，≤128 字符，幂等键
buttons[].typeroute（应用内跳转）/ url（外链，需域名白名单）/ callback（回传事件）/ event
方向约束：内联按钮只允许「公众号 → 用户」方向；用户消息不能携带按钮，违反返回 1003。 url 类型按钮的域名需先在开放平台完成域名校验，否则发送失败。

6自定义菜单

菜单是用户在公众号会话底部看到的按钮组，支持多级与版本回滚。

POST /official/menu/save       { "accountID": "...", "menu": { ... } }
POST /official/menu/publish    { "accountID": "...", "menuRevisionID": "..." }
POST /official/menu/get        { "accountID": "..." }
POST /official/menu/resolve    { "accountID": "...", "payload": "key" }
POST /official/menu/revisions  { "accountID": "...", "limit": 20 }
POST /official/menu/rollback   { "accountID": "...", "menuRevisionID": "..." }
POST /official/menu/callback   { "accountID": "...", "key": "...", "payload": "..." }
  • 草稿 → 发布：save 只保存草稿，publish 才生效；历史版本可用于回滚。
  • 菜单点击：客户端点击后走 /official/menu/callback，带上菜单项的 key 与 payload，由你的服务决定后续动作。

7自动回复

POST /official/reply/save   { "accountID": "...", "trigger": "keyword", "keyword": "人工", "reply": "正在转接客服…", "enabled": true }
POST /official/reply/list   { "accountID": "..." }
POST /official/reply/delete { "accountID": "...", "id": "..." }

trigger 支持关键词触发；命中后自动回复用户，不需要你的服务在线。
