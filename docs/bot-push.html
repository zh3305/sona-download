机器人与消息推送接入

开放平台应用（下称「机器人」）用于把外部系统接进 Sona：拿到用户授权与身份、接收事件回调、 按需给用户推送消息。本文覆盖应用创建、OAuth 授权、请求签名、事件回调与推送落地。

!能力边界（先看这条）

开放平台本身不发消息。它负责「身份 + 授权 + 事件」；真正的消息推送走公众号接口 POST /official/message/send。
所以一个完整的「机器人推送」需要：开放平台应用（拿 openID 与事件） + 公众号（发消息的载体）， 并由运营侧把二者绑定（/workbench/binding/create，绑定 公众号 · 商户 · 应用）。
能力归属说明
用户授权 / openID开放平台 /open/*OAuth2 + PKCE，返回应用内唯一 openID
事件回调开放平台 /open/callback/*授权撤销等事件推送到你的服务，支持失败重投
发消息给用户公众号 /official/message/send用户需关注该公众号
收用户消息公众号 webhookOpenIM afterSendSingleMsg 回调

1创建应用

POST /open/app/create
{
  "name": "订单通知机器人",
  "redirectURIs": ["https://your-service.com/oauth/callback"],
  "scopes": ["profile.nickname", "profile.avatar"]
}

凭据

  • 创建后返回 appID 与 keyID；secret 只返回一次，服务端仅存密文，丢失只能轮换。
  • POST /open/secret/list | rotate | revoke 管理密钥；轮换后旧 key 有过渡期（validUntil）。
  • 可用 scope 仅两个：profile.nickname、profile.avatar，一次申请 1–2 个。

2OAuth 授权（PKCE）

应用生成 code_verifier（随机串）并计算 code_challenge = BASE64URL(SHA256(verifier))。
调用 /open/authorize/prepare 发起授权，带上 redirectURI、state、codeChallenge、scopes。
用户在 Sona 内确认授权 → /open/authorize/confirm，回调你的 redirectURI 并带 code 与 state。
用 code + codeVerifier 调 /open/token 换 access_token / refresh_token。
令牌过期调 /open/refresh；解绑调 /open/revoke。
POST /open/authorize/prepare
{ "appID": "app_xxx", "redirectURI": "https://your-service.com/oauth/callback",
  "state": "csrf-token", "codeChallenge": "<BASE64URL(SHA256(verifier))>",
  "scopes": ["profile.nickname"] }

POST /open/token                        // 需带请求签名
{ "appID": "app_xxx", "code": "...", "codeVerifier": "...", "redirectURI": "..." }
用户身份：令牌换取的是应用内 openID（同一用户在同一应用下恒定、跨应用不同）， 不要把它当作 Sona 的 userID 使用。

3请求签名

除授权页外，所有 /open/* 请求都要签名。签名覆盖原始请求体字节，不要先解析再序列化。

3.1 请求头

头说明
X-Key-ID密钥 ID（轮换后可能有多个）
X-TimestampUnix 秒；允许 -300s ~ +30s
X-Nonce一次性随机串，服务端去重防重放
X-Signature下述算法的十六进制结果

3.2 签名串

POST
{path}                       // 如 /open/token
{timestamp}                  // Unix 秒，字符串
{nonce}
{SHA256_hex(raw body)}

signature = HMAC_SHA256_hex(appSecret, 以上 5 行用 \n 连接)

3.3 参考实现

// Node.js
import crypto from "node:crypto";

function sign(secret, path, timestamp, nonce, rawBody) {
  const digest = crypto.createHash("sha256").update(rawBody).digest("hex");
  const payload = ["POST", path, timestamp, nonce, digest].join("\n");
  return crypto.createHmac("sha256", secret).update(payload).digest("hex");
}

// Python
import hashlib, hmac
def sign(secret, path, timestamp, nonce, raw_body: bytes) -> str:
    digest = hashlib.sha256(raw_body).hexdigest()
    payload = "\n".join(["POST", path, timestamp, nonce, digest]).encode()
    return hmac.new(secret.encode(), payload, hashlib.sha256).hexdigest()

4事件回调

4.1 先校验回调域名

回调地址的域名必须先证明归属，否则无法保存配置。

POST /open/domain/prepare   { "appID": "app_xxx", "host": "your-service.com" }
// 返回 challenge，需在你的域名下暴露可校验内容
POST /open/domain/verify    { "appID": "app_xxx", "host": "your-service.com" }
POST /open/domain/list      { "appID": "app_xxx" }

4.2 配置回调

POST /open/callback/configure
{ "appID": "app_xxx", "endpoint": "https://your-service.com/sona/events", "enabled": true }

4.3 事件与签名

POST {endpoint}
X-Event-ID: evt_xxx
X-Timestamp: 1794400000
X-Signature: <hex>

{
  "eventID": "evt_xxx",
  "type": "authorization.revoked",
  "appID": "app_xxx",
  "openID": "openid_xxx",
  "occurredAt": "2026-11-14T12:00:00Z"
}
signature = HMAC_SHA256_hex(appSecret,
  ["HYIM-CALLBACK-V1", eventID, timestamp, SHA256_hex(raw body)].join("\n"))
当前事件类型：authorization.revoked（用户取消授权 / 解绑）。 收到后应按 openID 停推该用户，并清理本地映射。

4.4 投递失败与重投

POST /open/callback/get             { "appID": "app_xxx" }
POST /open/callback/delivery/list   { "appID": "app_xxx", "limit": 50 }
POST /open/callback/delivery/retry  { "appID": "app_xxx", "deliveryID": "..." }

投递失败会进入投递队列并保留记录，可用 delivery/retry 手动重投；建议你的回调幂等处理 eventID。

5消息推送落地

拿到 openID 对应到 Sona 用户后，用公众号账号发送消息（用户需已关注该公众号）：

POST /official/message/send
{
  "accountID": "official_10001",
  "userID": "8454036619",
  "kind": "text",
  "body": "订单 #20261114 已发货",
  "clientReqID": "order-20261114-0001"
}
要点：clientReqID 是幂等键，重试必须复用同一个值； body 上限 2000 字符；需要按钮时在 buttons 里声明（仅公众号 → 用户方向）。 详见 公众号接入指南。

6端到端时序

用户在你的站点点击「用 Sona 登录」→ 你的服务调 /open/authorize/prepare 拿到授权地址。
用户在 Sona 确认 → 回调带 code → 你的服务 /open/token 换令牌，得到 openID。
运营侧把「公众号 · 商户 · 应用」绑定（/workbench/binding/create），并让用户关注公众号。
业务事件发生时，你的服务调 /official/message/send 推送。 clientReqID 用业务单号，保证重试不重发。
用户取消授权时，你收到 authorization.revoked 回调，停止推送。
